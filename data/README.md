# Data dictionary

Two linked tables, generated by [`../src/generate_data.py`](../src/generate_data.py) with seed
`42`. Regenerating produces byte-identical files on any Python 3.10+ (verified on 3.12 and
3.14). `hr.db` is the SQLite build of the same two tables and is not committed - run
`python3 src/build_db.py` to create it.

- **Reporting window:** 1 July 2025 - 30 June 2026
- **Snapshot date:** 30 June 2026
- **Population:** 4,000 employee records (3,443 active at the snapshot), 28,470 HR cases

---

## `employees.csv` - one row per employee

| Column | Type | Description |
|---|---|---|
| `employee_id` | text | Primary key, `E00001` format |
| `hire_date` | date | Start date |
| `exit_date` | date | Leaving date, empty for active employees |
| `exit_type` | text | `Voluntary` / `Involuntary`, empty for active employees |
| `exit_reason` | text | Stated reason, e.g. `Compensation`, `Career progression`, `Restructuring` |
| `country` | text | `IT`, `PL`, `DE`, `ES` |
| `site` | text | Work location (Milan, Krakow, Munich, Barcelona) |
| `department` | text | Customer Service, Operations, Tech, Sales, Finance, HR |
| `job_level` | text | `L1` (entry) to `L6` (senior leadership) |
| `gender` | text | `F` / `M` - used for the statutory pay-gap reporting items |
| `age` | integer | Age in years at the snapshot |
| `contract_type` | text | `Permanent` / `Fixed-term` |
| `work_model` | text | `Onsite` / `Hybrid` / `Remote` |
| `fte` | real | 1.0 full time, 0.8 part time |
| `base_salary_eur` | real | Annual base salary, gross, EUR |
| `salary_band_mid_eur` | real | Mid-point of the salary band for that country, level and department |
| `compa_ratio` | real | `base_salary_eur / salary_band_mid_eur` - position in band |
| `tenure_months` | integer | Months from hire to exit for leavers, to the snapshot for active employees |
| `months_since_promotion` | integer | Months since last level change (since hire if never promoted) |
| `performance_rating` | integer | Last review, 1 (lowest) to 5 (highest) |
| `engagement_score` | integer | Latest survey score, 5-100 |

## `hr_cases.csv` - one row per HR service-desk case

| Column | Type | Description |
|---|---|---|
| `case_id` | text | Primary key, `C000001` format |
| `employee_id` | text | Foreign key to `employees.csv` - the employee who raised the case |
| `created_date` | date | Case opened |
| `resolved_date` | date | Case closed |
| `country`, `department` | text | Copied from the requesting employee |
| `category` | text | Payroll, Leave & Absence, Contract & Documents, Benefits, Systems & Access, Onboarding & Offboarding, Performance & Development, Employee Relations |
| `priority` | text | `Standard` / `High` / `Critical` |
| `channel` | text | `Portal` / `Phone` / `Chat` |
| `agent_id` | text | HR agent who handled the case |
| `agent_tenure_months` | integer | That agent's experience in months |
| `sla_target_hours` | integer | Resolution target for the category |
| `resolution_hours` | real | Elapsed hours from creation to resolution |
| `sla_met` | integer | 1 if `resolution_hours <= sla_target_hours` |
| `first_contact_resolution` | integer | 1 if closed without a hand-off |
| `reopened` | integer | 1 if the employee had to reopen the case |
| `csat` | integer | Satisfaction 1-5, empty where the employee did not answer the survey (~55% of cases) |

## What is deliberately planted in the data

A generator that produced pure noise would make the analyses meaningless, and one that produced
clean textbook effects would make them dishonest. These are the mechanisms built in, stated
openly so the analyses can be judged on whether they find and size them correctly:

| Mechanism | How it is built | Where it shows up |
|---|---|---|
| **Vertical segregation** | Share of women falls from 62% at L1 to 15% at L6 | Most of the 15.4% raw pay gap |
| **Horizontal segregation** | Women concentrated in lower-paying functions (Customer Service, HR), men in Tech | Part of the gap that job level alone does not explain |
| **Small residual pay effect** | A deliberate -2.1% within level and country | The like-for-like gap the regression recovers at ~1.6% |
| **Exit hazard** | Monthly logistic hazard driven by compa-ratio, promotion stagnation, engagement, contract type, first-year tenure, department and case friction | The driver model's odds ratios |
| **Case friction** | A latent per-employee trait that raises both reopened cases and exit hazard | The cross-dataset finding linking service quality to retention |
| **Seasonality** | Payroll cases peak in January (tax and pay review), leave cases before summer and at Christmas | The volume curve |
| **Queueing** | Agent capacity is flat, so handling time stretches super-linearly with monthly load | SLA attainment collapsing at the January peak |
| **Survey bias** | CSAT collected on ~45% of cases, and unhappy experiences score lower | The CSAT-by-experience chart |

Noise is applied on top of every mechanism, and sample sizes are realistic - which is why some
effects in the report come out significant and others honestly do not.
